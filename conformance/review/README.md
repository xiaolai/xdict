# Review conformance

`parity-vectors.json` — **2,000 FSRS-6 transitions** from XiaolaiDict's executable specification
(`Tools/fsrs/vectors.py` over `fsrs6.py`, upstream py-fsrs commit `9446cb0`, MIT licence in `UPSTREAM-LICENSE.txt`);
version `fsrs6-py9446cb0-one10m-no-fuzz-v1`. Every transition carries a retention, a grade, an instant, the state
before and the state after.

`xdict-schedule`'s `tests/parity.rs` reproduces every one of them **bit for bit** (`to_bits` on every float, exact
phase, last-review and due); a one-ULP change in a weight turns it red. Regenerate the fixture only when the kernel's
numbers are meant to change, and expect the gate to go red when they do — that is the gate working.

The MIT notice must travel with the fixture: the formulas and parameters are derived from py-fsrs.

The parity test parses the fixture with serde_json's `float_roundtrip` feature. Without it, serde_json's fast path can
read a double one ULP off and a correct port looks like a scheduler defect (found 2026-10-21, transition 7).

## The Windows-qualified fixture

`parity-vectors-windows.json` is the same seeded walk, generated by the same Python spec on **Windows 11, Python
3.14.7**. Windows' UCRT libm rounds the first difference at transition 26 one ULP away from the platform that made
the shared fixture, and the walk carries it forward: 61 inputs and 65 after-states differ from
`parity-vectors.json`. The Windows port reproduces this fixture bit for bit; the shared fixture stays the reference
for macOS, Linux and the other bindings. `tests/parity.rs` selects it on `cfg(windows)`.

The spec is XiaolaiDict's `Tools/fsrs/vectors.py` over `Tools/fsrs/fsrs6.py` at commit
`044dac63c580b641613f4a68d7a15ec918818d81` (its `VERSION` is `fsrs6-py9446cb0-one10m-no-fuzz-v1`, the py-fsrs commit
`9446cb0`). From that checkout:

    python.exe Tools/fsrs/vectors.py > <XDict>/conformance/review/parity-vectors-windows.json

The command's output is CRLF on Windows; it was converted to LF, as the checked-in file is. The generation is
recorded here with the Python version because the fixture is a platform one: regenerating it on another Python or
OS is a different fixture, and the gate goes red when the kernel's numbers move.

The one-ULP mutation gate runs on both fixtures. A one-ULP change to a transition turns the parity test red; a
one-ULP change to a weight turns `a_one_ulp_mutation_is_refused` red. Recorded 2026-11-01: transition 0's stability
was moved to the next double, both tests failed, and the fixture was restored.
