# **The only list of the end-to-end sub-stages and the checks each owns** (`Tools/e2e.sh`, `Tools/e2e-plan.sh`).
#
#   @ <sub-stage> <default|extra> <needs> [group=<name>]
#       <check> <check> …
#
# A sub-stage is `<stage>.<part>`, or a bare stage that has no parts (`launch`, `reader`). The order here is the order
# they run in: cheapest first, as measured by the last full run. `default` sub-stages are what a bare stage name, a run
# with no STAGES, and a release (`Tools/e2e-status.sh require-fresh`) mean; `extra` ones run only when named.
#
# <needs>, comma separated or `-`: `kit` the entry view's kit (Tools/build-lab.sh), `fixtures` Tools/build-fixtures.sh's
# dictionaries, `sample` entries_corpus's sample of the owner's dictionaries, `editions` index_bench's editions of them,
# `corpus` the owner's dictionaries themselves. A `group` is one launch that serves several sub-stages (the lookup
# window): it runs once for whichever of them are asked, and each check is still recorded under its own sub-stage.
#
# **Every check belongs to exactly one sub-stage**: the run records a check under the sub-stage named here, whichever
# launch reported it, and a sub-stage that never reported one of its checks fails. `Tools/tests/e2e-plan-test.sh` holds
# this list to `Tools/tests/e2e-checks-baseline.txt`, the checks of the full run before the stages were split.
#
# Instrument checks are the names in their `Findings`; the shell's own assertions are named here; the analyzers'
# verdicts (`Tools/hostile/analyze.py`, `Tools/lookup/verdicts.py`) are one check per analysis, every line of it
# recorded under that name.
